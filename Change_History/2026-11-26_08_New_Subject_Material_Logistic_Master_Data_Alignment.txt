WHY
- Manager request (2026-11-26): add a new Subject "Material Logistic Master Data Alignment", and
  remove the line  "11.0", "PS-MLA Master Data",  from the "// Material Master" part of the
  Subject box's OnChange.
- Decisions (Nofil, 2026-11-26): it is a new Subject in the dropdown; Assigned Department: none
  (left blank, the user picks one).
- How subjects work (CONFIRMED in the code): the list is colSubjects in App.OnStart, one
  {Key, Value} per subject. Users see Value (no number); the query saves Key (with number).
  pnqSubject.OnChange has a Switch that maps each Key to the Assigned Department.
- The line "11.0", "PS-MLA Master Data" never ran: no subject has the Key "11.0". So removing it
  changes nothing by itself.
- The new subject follows the same pattern:
    Key   (saved)  = "11.0 Material Logistic Master Data Alignment"
    Value (shown)  = "Material Logistic Master Data Alignment"
  It goes into the list between "10.9 Excess & Inactive Inventory Request" and
  "12.0 MAG Certification" (same order as the numbers), and its Switch line maps it to Blank()
  (no department), in the place of the removed "11.0" line.
- Exact text to confirm with the manager before pasting: "Logistic" (not "Logistics"), as given.
  The saved Key is permanent in the data once queries are saved with it.

IMPACT / RISK
- Two properties: App.OnStart (ONE line added to the colSubjects list, nothing else) and
  pnqSubject.OnChange (ONE line replaced). Nothing else changes: Items, SearchItems,
  DisplayFields, SearchFields, DefaultSelectedItems, the save code, data sources and flows.
- The new subject appears in the Subject dropdown for new and existing queries (record 07's Items
  filter only hides "PS-MLA Master Data"). It shows without the number, like the others, and can
  be found by typing (SearchItems searches colSubjects' Value, which now includes it).
- Picking it works exactly like "12.0 MAG Certification" today: the Assigned Department box and the
  Assigned To list are emptied, and Save asks "Please select an Assigned Department" until the
  user picks one. On an existing query the department is cleared too; picking a different one
  than before asks for a comment on Save (as today for any department change).
- Saving writes Key "11.0 Material Logistic Master Data Alignment" to the Subject column
  (text, max 4000 characters; longest existing Key is 71 characters). The home "By Subject" filter,
  galleries and the Export-iQuery-ReportData flow read the saved text, so the new subject appears
  there once a query is saved with it. No flow checks subject names (searched all 3 flows).
- No other place in the app lists subject names or reads the number (searched the whole app: SLA
  uses priority and department only; Misses tracker, Admin and Feedback screens don't use it).
  Reports outside the app (Power BI, Dataverse views) were not checked.
- After this record, record 07 test 1 expects 53 other subjects (not 52).
- Users with the app already open before publishing keep the old list: they can't pick the new
  subject, and a query saved with it shows an EMPTY Subject box for them (Save would ask for a
  subject). After publishing, ask users to close and reopen iQuery (refresh the browser tab).
- If App.OnStart is pasted wrongly the whole app can fail to start: copy the AFTER exactly and
  test in Studio (Run OnStart) before publishing.
