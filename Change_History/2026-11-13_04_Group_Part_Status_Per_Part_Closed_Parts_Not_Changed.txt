WHY
- When you click Edit Form on ONE part of a group, the grey cover Container31 lies over the
  whole of section 1, including Status. So one part can't be closed (or set to Interim) on its
  own; the only way is "Edit whole group", which closes every part.
- The save for one part already works per part: the "Update single" branch of HiddenSaveButton
  writes Status, Date Closed, Solution and Quality to that part only. Only the screen blocks it.
- "Edit whole group" saves with UpdateIf(... BatchDocNo = group ...): it writes every field,
  including Status, Date Closed, Solution and Quality, to EVERY part (closed ones too), adds the
  history comment to every part and a Misses Tracker row to every part. It also writes the Status
  of the part you opened to every part, even if you didn't touch Status.
- After saving one part of a group the tab stays open on purpose (btnSaveClose opens the
  "Assignment Confirmation" pop-up so HiddenSaveButton keeps the tab). For a Close, the
  "Close iQuery" pop-up would stay on screen and a second click would save the comment twice.
- "Edit whole group" (Button9) is refused when ANY part is in another department, also a closed
  part.

HOW GROUP EDIT DECIDES STATUS (keep this for checking later)
- At the start of a group save, HiddenSaveButton sets varGroupStatusChanged:
    true  = the tab's fieldsUpdated list has a row with FieldName "Status"
    false = it has not
- fieldsUpdated gets a "Status" row only from cmbStatus.OnChange, when you pick a Status that is
  different from the saved Status of the part you opened. The row is removed again if you pick
  the old Status back, or press Cancel / X / the grey background on the "Close iQuery" pop-up.
  So: true = "the user changed Status in this group edit".
- varGroupStatusChanged = true : every OPEN part gets the Status from the Status box and the
  Date Closed from dtpClosedDate (today when closing).
- varGroupStatusChanged = false: every OPEN part keeps ITS OWN Status (Open or Interim) and ITS
  OWN Date Closed. All other fields are still written as before.
- Closed parts are never written in a group save (they are not in colGroupOpenParts).
- How to check afterwards, in the data: the group save writes ONE history comment per open part.
  If its "Field Updated" contains "Status", the Status/Date Closed were written to every open
  part; if it does not, every open part kept its own Status.
  ALSO check the part's own row in PNQ_Backlogs (Status and Date Closed). The history comment is
  written in a separate step, so if a database write failed (an error banner appears), the
  history can say "Status" while the PNQ_Backlogs row was not changed. The row is the truth.
- Known limit: when Status IS changed in group edit, each part's history shows the old Status of
  the part you opened (e.g. "Open -> Closed" also for a part that was Interim). The new Status is
  correct on every part. This is the same as today.
- Known limit: you can't use group edit to set all open parts to the Status the opened part
  already has. Example: you open part C (Open) and part A is Interim; picking "Open" is no change
  for C, so no "Status" row is added and A stays Interim. Set A on its own instead (Edit Form on A).
- The "Status" row can carry over in two cases; both match what the Status box shows:
  - You change Status on one part, then click "Edit whole group" (Button9 doesn't clear the list):
    the new Status goes to every open part when you save the group.
  - Edit session timed out, then Edit Form again (btnUpdate_1 doesn't clear the list): a Status
    change made before the timeout is still applied on Save.

IMPACT / RISK
- Not changed: data sources, flows, App.OnStart, colOpenTabs fields, btnSaveClose, Form1, the
  "Close iQuery" pop-up, the grey covers (Container31...), attachments (record 03), new requests,
  the one-part save branch (except the tab now closes after a Close), other screens.
- One part of a group (yours, your department): only Status (and its label) comes in front of
  the grey cover; the rest of section 1 stays covered. Closed -> usual "Close iQuery" pop-up
  (Solution + Quality) -> only this part is saved, then the tab closes. Open/Interim -> reason
  box as today -> only this part changes; the tab stays open as today for a part of a group.
- Status box while editing a query that isn't yours / is in another department: Disabled
  (CHANGE 1, same rule as the cover) - before, the cover blocked it. New requests can still set
  Status. The view-mode rule for the one Configuration Management user is unchanged.
- Group save: only parts that are not Closed get fields, the history comment and the Misses
  Tracker row; the success message lists only them. The two UpdateIf calls became ForAll +
  Patch(LookUp(... DocNo = part)) (same pattern as the one-part save); same fields and values,
  except Status / Date Closed (see above). Query_Details rows are now found by DocNo instead of
  Query_Details.BatchDocNo: same rows when BatchDocNo is filled (the create path fills it); an
  old first part with a blank Query_Details.BatchDocNo is now also updated (correct). The
  Query_Details Patch is skipped if a part has no Query_Details row.
- The group save still clears the edit lock of every OPEN part, as before.
- New names (only here, checked not to exist in the zip): collection colGroupOpenParts and
  variable varGroupStatusChanged, set only in HiddenSaveButton's group branch, on every save.
- Tab closing: the tab now also closes when the Status saved is Closed. Normal queries and group
  edit already did. Only other case that changes: a NEW request assigned to yourself with Status
  Closed now closes the tab after saving.
- "Edit whole group" (Button9): a closed part in another department no longer blocks it. The
  lock check is unchanged.
- Files stay shared by the group (stored on the first part, Form1.Item), also when the first
  part is closed: a file added after a part was closed also shows on that closed part.
- Assumption: every part has a Status (Save requires one). Dataverse likely leaves a part with a
  BLANK Status out of "Status <> Closed", so group edit would not change it (very old data only).
- Look: for a query that isn't yours, Status is a greyed-out box in front of the cover. The
  group-edit bar text is longer and may be cut off on a narrow screen (Label41 doesn't wrap).
- Delegation: the new Filters use the same Status <> Closed filter the app already runs on
  PNQ_Backlogs.
- Review 2 points, NOT fixed (rare or same as today), recorded so we can decide later:
  1. A part closed by another user DURING the few seconds of the group save still gets this
     save's fields/history/Misses Tracker row (and Status, if changed). A part closed any time
     before Save is clicked is correctly left out. When Status is not changed, each part's own
     fresh Status/Date Closed are written back (not left out of the Patch); same result except
     in that same tiny window.
  2. No error handling on failed writes (same as today, no IfError anywhere in the save): after
     a failed Patch (error banner), the history comment and the success message can still name
     that part. Check the PNQ_Backlogs row, not only the history.
  3. Button9's lock check still looks at closed parts too (Query_Details has no Status column).
     In practice a closed part has no lock: Edit Form is hidden on closed parts and every save
     that closes a part clears its lock.
- Existing, not changed: after saving one part, the success message shows the group's FIRST
  Doc No. If user X has Edit Form open on a part while Y (whose group edit started earlier)
  closes the group, X's later Save writes X's Status back (two people editing at once).
