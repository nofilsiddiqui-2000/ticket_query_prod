WHY
- Reported (Nofil, 2026-11-15): "Edit whole group" + comment + Save goes back to the home
  list, but Edit Form on ONE part of a group + comment + Save keeps you on the query in edit
  mode. Every successful Save should leave edit mode.
- Cause: at the end of HiddenSaveButton.OnSelect the tab is closed UNLESS the flag
  showAutoAssignConfirmModal is on (and the query is yours, and Status isn't Closed).
  btnSaveClose.OnSelect turns that flag on for one part of a group that is yours,
  "// to stay on the same screen". The block is in every export we have, back to the oldest
  (last saved 2026-11-04, prod v1.51), so it is the main developer's design, not ours.
- The same flag is set by "Assign to yourself" (or by picking yourself in Assigned To), and
  it is also what shows the "Assignment Confirmation" pop-up. So "Assign and Save" also kept
  the tab open in edit (single query, one part, whole group, and a New Request where you
  picked yourself). Nofil chose (2026-11-15) that this should close too.
- Staying open was also risky: the save had already released the edit lock (someone else
  could open Edit Form on the same part), and the comment box isn't cleared, so a second
  Save would post the same comment again.

IMPACT / RISK
- Only what happens AFTER a successful save changes. Validation, the "please add a comment"
  rules, all database writes, comments, Misses Tracker, files and the refresh are unchanged.
- One part of a group (yours): Save -> saved -> home list (was: stayed in edit).
- "Assign to yourself" -> "Assign and Save" (single, one part, whole group, New Request where
  you picked yourself): saved -> home list (was: stayed in edit). To keep working on it,
  open it again and click Edit Form.
- Single query, whole group, normal New Request, Status Closed, reassigned to someone else:
  already closed, still close.
- On one part of a group, the "Assignment Confirmation" pop-up no longer appears during the
  save (CHANGE 1). That flag was on while the files uploaded, so the pop-up and its
  "Assign and Save" button were most likely visible on a part that is already yours.
- Form1.DefaultMode: unchanged. A query that is yours is in Edit. For "Assign and Save" the
  flag is still on during SubmitForm (set by "Assign to yourself"), as before, so files
  still save.
- Form1.OnFailure (record 03 CHANGE 4): not changed. On one part the flag is now already
  off, so its Patch does nothing there. Its code comment ("Save itself opened the pop-up")
  is now out of date (cosmetic only, left alone).
- The record 04 condition 'Text(cmbStatus.Selected.Value) = "Closed"' goes away with the If.
  A Closed save closes the tab like every other save now.
- Existing, not changed: on "Assign and Save" for a query that isn't yours, btnSaveClose
  doesn't show validation errors and saves anyway (for example a field changed without a
  reason). The only difference now is that the tab closes afterwards.
- Existing, not changed (record 04 known limit 2): no error handling on the database writes.
  If a write fails, Power Apps shows its red error banner, but "Record saved successfully"
  still shows. Single query, whole group and New Request already closed the tab after a
  failed write. Now one part and "Assign and Save" do too. Before, staying open there didn't
  help either: the app had already treated the save as done (values copied, changed-fields
  list emptied, lock released). Error handling is planned as its own change.
- No new data calls -> no new delegation warnings. Callers checked: Save (btnSaveClose),
  "Assign and Save" (AutoAssign_Save_Button) and "Save & Close Request" (Close_Button_4) all
  go through btnSaveClose. Form1.OnSuccess is the only Select(HiddenSaveButton).
  UploadAttachmentBtn's SubmitForm doesn't run HiddenSaveButton (uploadButtonClicked).
