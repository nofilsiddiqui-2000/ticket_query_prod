WHY
- Reported (Nofil, 2026-11-15): "Edit whole group" + comment + Save goes back to the home
  list, but Edit Form on ONE part of a group + comment + Save keeps you on the query, still in
  edit mode.
- Cause: at the end of HiddenSaveButton.OnSelect the tab was closed UNLESS the flag
  showAutoAssignConfirmModal was on (and the query was yours, and Status wasn't Closed).
  btnSaveClose.OnSelect turned that flag on for one part of a group that is yours,
  "// to stay on the same screen". This was in every export back to the oldest (last saved
  2026-11-04, prod v1.51), so it is the main developer's design. The same flag is set by
  "Assign to yourself", so "Assign and Save" also stayed in edit mode.
- Staying in edit was risky: the save had already released the edit lock (someone else could
  open Edit Form on the same part), and the comment box wasn't cleared, so a second Save
  posted the same comment again.
- Wanted (Nofil): after EVERY successful Save, leave edit mode but stay on the same query
  (view mode). New Request still goes to the home list (there is no query tab to show yet).

IMPACT / RISK
- Only what happens AFTER a successful save changes. Validation, the "please add a comment"
  rules, all database writes, comments, Misses Tracker, files and the refresh are unchanged.
- Existing query (single, one part of a group, whole group, "Assign and Save", Status Closed,
  reassigned to another person or department): the tab stays open in VIEW mode. The query is
  read again from Dataverse (2 extra reads: PNQ_Backlogs and Query_Details, by Doc No).
  - Before: single query, whole group, Closed and reassigned closed the tab. One part and
    Assign and Save stayed in EDIT mode.
  - Edit Form is visible again (not for Closed). Clicking it locks and edits as usual. After
    "Assign and Save" you are the owner, so Edit Form lets you edit straight away.
  - "Edit whole group": you come back to view mode on the part you opened it from. The group
    bar, the "Edit whole group" button and the grey covers are hidden (they need edit mode).
  - Pop-ups ("Assignment Confirmation", "Close iQuery", timeout) are closed. The edit timer
    stops. The comment box is emptied (Reset), so the next edit starts empty.
  - The SLA panel (Timer1) is worked out again for this query, as when a tab is opened.
- New Request (1 or more parts, also when you picked yourself in Assigned To): the tab
  closes and you go to the home list. Before, "pick yourself" + "Assign and Save" kept the
  New Request tab open, and a second Save could try to create the same Doc No again.
- If the query can't be read back after the save (blank or error, rare): a warning "Saved.
  This query could not be shown again: open it from the list." and the tab closes (home list),
  so it never stays in edit mode without its lock and never looks like a New Request.
  A query that has no Query_Details row still stays open (same as opening it from the list).
- On one part of a group, the "Assignment Confirmation" pop-up no longer appears during the
  save (CHANGE 1). While the files uploaded it was on screen, and its "Assign and Save" could
  start a second save.
- Form1: switches to View after the save and shows the files read again. Form1.OnFailure
  (record 03 CHANGE 4) isn't changed. On one part its Patch does nothing now. Its code comment
  ("Save itself opened the pop-up") is out of date (cosmetic, left alone).
- Delegation: the 2 new reads use a global variable (varSavedDocNo), the same pattern as
  opening a query (Gallery6). No With-record field is used inside a Dataverse filter. No new
  App Checker item is expected.
- Existing, not changed:
  - On "Assign and Save" for a query that isn't yours, btnSaveClose doesn't show validation
    errors and saves anyway.
  - The Zendesk / Salesforce boxes write a wrong field name while you type (TicketCaseNumber).
    The save itself writes the right values, and the read-back now shows them. But changing
    ONLY one of those numbers, with no comment, still gives "No changes made". Not a regression.
  - No error handling on the database writes (record 04 known limit 2). Planned as its own
    change after this one is tested.
  - During a file upload the screen can be clicked. Don't switch tabs until "saved
    successfully" shows (true for all saves).
  - An open tab is never refreshed if someone else changes the query later (true for any
    open tab today).
