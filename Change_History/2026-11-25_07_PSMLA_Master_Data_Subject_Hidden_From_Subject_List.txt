WHY
- Request: when users create a new query, the Subject dropdown must no longer offer
  "PS-MLA Master Data". Old queries already saved with that subject must keep working.
- The subject list is the collection colSubjects (App.OnStart; last entry
  {Key:"PS-MLA Master Data", Value:"PS-MLA Master Data"}). It is shown by one control, the Subject
  box pnqSubject, used for NEW and for EXISTING queries.
- We don't delete the entry in App.OnStart: old PS-MLA queries would open with an EMPTY Subject
  box (DefaultSelectedItems looks the subject up in colSubjects), and Save would stop with
  "Please select Subject", forcing users to change the subject of old queries.
- Why versions 1 and 2 did nothing (CONFIRMED from Controls/*.json): pnqSubject is a Classic
  ComboBox with "Allow searching" on (IsSearchable = true). Such a box fills its dropdown from a
  HIDDEN property, SearchItems, not from Items. SearchItems is not in the property dropdown and
  not in the Src/*.pa.yaml files; it is only in Controls/*.json. It was still
      Search(colSubjects, pnqSubject.SearchText, Value)
  (made by Studio when Items was plain colSubjects), so the dropdown always showed the full list.
  Studio did not rebuild it for the With(...) and If(...) formulas.
- Not the cause: DefaultSelectedItems (only picks the selected item; blank on a new query) and
  the "11.0" line in OnChange (only sets the Assigned Department, for a subject that is not in
  the list).
- Fix: Items = one plain Filter (no With / If) that hides PS-MLA unless the open query is already
  saved with it, and Studio rebuilds SearchItems from it.

IMPACT / RISK
- Only pnqSubject: Items, and the hidden SearchItems rebuilt by Studio. DisplayFields and
  SearchFields must stay ["Value"] (as before), so the list keeps showing names without numbers.
  App.OnStart, colSubjects,
  colOpenTabs, the save code (btnSaveClose, HiddenSaveButton), data sources and flows are NOT
  changed.
- New query (single or multi-part, New Request button): PS-MLA is not offered.
- Existing query with another subject: PS-MLA is not offered (nobody can switch to it).
- Existing query already saved with PS-MLA: still shows it, saves normally, can be changed to
  another subject (and back, until it is saved).
- Home list "By Subject" filter reads subjects from the data, so old PS-MLA queries can still be
  found. The Assigned Department "PS - MLA Master data" is not affected.
- colSubjects is a local collection: no delegation warning.

Checked from Controls/*.json (all pnqSubject properties) and the whole app.

  Export-iQuery-ReportData (raw cr7ba_requestsubject), Admin_Screen, Feedback_Screen.

  If A was already editing when B saved, last save wins (same as before).

  pnqSubject SearchItems must contain Key <> "PS-MLA Master Data", IsSearchable = true,
  DisplayFields = SearchFields = ["Value"], Items = v3.
