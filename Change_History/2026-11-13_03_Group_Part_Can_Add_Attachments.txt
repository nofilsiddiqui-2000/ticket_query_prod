WHY
- Files are stored once per group, on the FIRST query of the group (Form1.Item uses the
  BatchDocNo), so every part already shows the same file list.
- When you click Edit Form on ONE part of a group, Form1.DefaultMode has an extra block
  ("part of a group, not in group edit -> view only"). So you can see the files but not
  add any, even when the part is assigned to you. Today the only way to add a file is
  "Edit whole group".
- The rest already works: on one part, Save (btnSaveClose) already switches Form1 to Edit
  just before SubmitForm(Form1) (it sets showAutoAssignConfirmModal = true "to stay on the
  same screen"), so the picked files are saved, and the comment goes into THIS part's
  history (HiddenSaveButton, one-part save).
- The attachment box is only 100 px high. With 2 files, the "Attach file" link is below
  the visible part and you must scroll inside the box to find it (reported in dev on
  2026-11-13, one part in edit mode with 2 files). CHANGE 5-8 make the box 60 px taller.
Rules (from #14, Nofil 2026-11-05):
1. On one part, the person it is assigned to, in their department, can add files ("Assign
   to yourself" first, as for any change). The file goes to the whole group.
2. Files are saved with Save, and a comment is required ("attaching drawing XYZ"). The
   comment is the history entry (name, department, time). The Upload button stays hidden
   on one part.
3. One part can never remove files (they belong to the whole group).

IMPACT / RISK
- CHANGE 1-4 (who can add files): Form1.DefaultMode, btnSaveClose.OnSelect (one text
  only), DataCardValue4.OnRemoveFile (was empty), Form1.OnFailure (one Patch added after
  the existing Notify).
- CHANGE 5-8 (size only, numbers): attachment box 100 -> 160, Form1 111 -> 171, section 3
  (Container 3) 60 px taller when open (580 -> 640, or 850 -> 910 when the query has old
  PNQ attachments), the "Old PNQ attachments..." banner 60 px lower (608 -> 668).
  Everything else in the section moves by itself: the old attachments label/box and
  lblOR are placed from Form1.Y + Form1.Height, the Upload button from Form1.Y. The
  sections below move down by themselves (newQueryMainContainer stacks the sections and
  scrolls). The banner is the only control with a fixed Y below the box, so it is moved by
  hand. Section 3 closed (30 px) is unchanged. Applies to every query, not only groups.
- CHANGE 1, only one case changes: editing one part of a group, assigned to you, your
  department -> attachment box editable (was view-only). Not assigned, other department,
  view mode, group edit, New Request and normal queries behave exactly as before.
  The grey cover in that section (Container31_2) stops above the attachments label, so the
  box is not covered.
- Saving: no logic change. Form1 has only the Attachments card and a hidden DocNo card that
  writes back the same DocNo the form looked up, so the form writes nothing else.
- After a save on one part assigned to you, the tab stays open in edit and the message
  shows the FIRST query's Doc No (both existing behaviour).
- CHANGE 2: the "No changes made." message now also says to add a comment when files were
  added. It shows in the same cases as before (no comment, no field change).
- CHANGE 3 runs only when a file is removed in the box on ONE part of a group. Everywhere
  else nothing happens (as today: no OnRemoveFile). OnRemoveFile and Reset() on the
  attachment box are not used anywhere else in this app -> T4 confirms them. If App
  Checker shows an error on Reset(DataCardValue4), stop and tell me.
- CHANGE 4 runs only when SubmitForm(Form1) fails, and only clears the pop-up flag when the
  query is assigned to you, in your department (the case where Save itself set it). Before
  this fix one part could not add files, so a failed save almost never happened there; now
  a too-big or blocked file can cause it, and the "Assignment Confirmation" pop-up would
  stay on screen. In the "Assign and Save" case nothing changes. On New Request, normal
  queries and group edit the flag is already false, so the Patch changes nothing.
  CHANGE 4 depends on CHANGE 1: without CHANGE 1, closing the pop-up would switch Form1
  back to View and drop the picked files. Never keep CHANGE 4 without CHANGE 1.
- After a successful save on one part the tab stays open and Form1 now stays in Edit
  (before, it went back to View). T1 checks the saved file is not attached twice.
- Edit Form locks only the part you clicked. Files on one part are written to the FIRST
  query's row, which that lock does not protect -> T10 covers two people at the same time.
- If Studio asks you to unlock Attachments_DataCard1 (CHANGE 3), that also changes the
  card's lock setting in the export. Expected, not a problem.
- Exception to rule 2 (same as normal queries today): if you also change a field and give
  its reason, Save works without a comment.
- Files are Dataverse Notes on the group's first Query_Details row. Two people saving files
  on the same group at the same time is not documented by Microsoft -> T9/T10 must pass
  before production.
- Not touched: data sources, flows, assignment, locks, history/comment code, the Upload
  button, the grey covers, HiddenSaveButton, other screens.
- Known limit: in old groups whose FIRST query has a blank BatchDocNo, that first query acts
  like a normal query (removing there is allowed, as today).
- Known limit (as today for every query): files picked but not saved are lost if you switch
  tabs or close the tab.
